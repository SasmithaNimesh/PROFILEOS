1. Overview
PROFILEOS is an AI-powered professional identity platform. Users bring in what they
already have (profile links, documents, manual entries), build one verified source of truth,
and turn it into career assets: a published portfolio, CVs, and cover letters.
This document defines the UI/UX approach for the redesign. Its central decision is a strict
separation of two experiences:
The workspace is never a crowded dashboard. Each major feature gets its own dedicated
page and workspace.
2. Design Principles
1. One screen, one job. Every page answers a single question: where am I, and what do I
do next?
2. Navigation hub, not feature dump. The Overview shows four actions and a progress
indicator, nothing more.
3. Truth over polish. AI never invents qualifications, dates, employers or metrics. Missing
data is requested or omitted.
4. Everything is editable. Generated content is always real, structured, editable content,
never a flattened image.
5. Show, then confirm. Imported data is presented for review before it joins the profile.
6. Real or absent. No dead buttons, fake analytics or placeholder pages. If an integration
lacks credentials, show a clear setup or unavailable state.

Rules: blue is the single primary action colour. Violet appears only in subtle gradients and
highlights. Gradients are never used on body text or large surfaces in the workspace.
6.2 Typography
Display: Space Grotesk, for hero and section headings.
Body and UI: Inter or Geist.
Scale: 12 / 14 / 16 / 18 / 24 / 32 / 48 / 64 px, with a clear step between heading levels.
Line height: 1.6 body, 1.1–1.2 display.
Weights: 400, 500, 600 for UI; 500–700 for display.
6.3 Spacing, shape, elevation
4 px base grid; common steps 8, 12, 16, 24, 32, 48, 80, 120.
Radius: 8 px controls, 12 px cards, 20 px large surfaces.
Elevation is expressed with borders and slight tonal shifts first, shadows second. Glow
is reserved for hero visuals and primary CTAs on the public site.
6.4 Core components
Buttons (primary, secondary, ghost, destructive), inputs with inline validation, selects, tag
inputs for skills, section cards with View/Add/Edit/Delete, modals and drawers, tabs,
toasts, skeleton loaders, empty states, stepper, split-pane layout, template picker card,
document card, version-history list, confirmation dialog.
Every component defines default, hover, focus, active, disabled, loading and error states.

7.4 Motion
Subtle fade-and-rise on scroll, slow parallax on hero graphics, hover lift on template cards.
Durations 200–500 ms with ease-out. All motion respects prefers-reduced-motion .
8. Authentication
Four pages in the public visual language: Sign In, Create Account, Forgot Password, Email
Verification.
Centred card on an obsidian background with a restrained glow.
Inline validation, visible password rules, show/hide password.
Clear error messages that say what to do next.
After success, route to onboarding (new users) or Overview (returning users). Never
to a crowded dashboard.
9. Onboarding

"Skip for now" action.
Design notes: one decision per screen; imported data is shown as a reviewable list with
accept, edit and discard per item; the user can leave and resume later from the profile
completion indicator.

10. Workspace Shell
Sidebar (slim, collapsible on desktop): Overview, My Profile, Portfolio Studio, CV
Studio, Cover Letter Studio, My Documents, Settings. Icon plus label; icon-only when
collapsed.
Top bar: current page title, notifications (only if needed), profile menu.
Mobile: bottom tab bar for the main destinations, with Settings in the profile menu;
studios use full-screen flows.
Layout: content max-width about 1200 px, generous padding, consistent page header
with title and one primary action.
The workspace uses a calm palette: charcoal surfaces, no particle or glow effects, accent
colour only for primary actions and focus.
11. Page Designs
11.1 Overview
Heading: "Welcome back. Let's build your professional identity."
Supporting text: "Your professional information, portfolio, and career documents — all
in one place."
Four understated cards: Create Portfolio, Create CV, Create Cover Letter, Manage
Profile. Each is fully clickable.
A small profile completion indicator, with a link to the next missing section.
Recent documents appear only when real data exists.
No fake charts or analytics.
11.2 My Profile
The single source of truth for all generation.
Sections: Basic Information, Social Profiles, Education, Qualifications, Work Experience,
Internships, Projects, Skills, Certifications, Achievements, Awards, Publications,
Volunteering, Languages, Interests, Professional Links.
Pattern: a left section list (or tabs on mobile) and a right editor. Each section supports
View, Add, Edit, Delete, Save and Cancel, with entries shown as compact cards that
expand into an edit form. Users can add custom sections.
Connect Your Professional World: a prominent panel for pasting URLs (LinkedIn, GitHub,
personal site, Instagram, Facebook, Behance, other) with platform icons and URL
validation. GitHub connects through its official API; LinkedIn only through officially

11.3 Portfolio Studio
Flow: Create Portfolio → choose type → choose template → select profile information →
customise visuals → generate → preview → edit → save or publish.
Types: One-Page (primary), Professional, Creative.
Templates (genuinely different layouts, not recolours):
Editor: a focused workspace with a section list (reorder, hide, add) on the left, a live
preview in the centre with desktop/mobile toggle, and a style panel (colours, fonts, profile
photo). Actions: Save draft, Publish, Unpublish.
Rendering: portfolios are rendered from a structured specification and reusable
components. No static screenshots and no execution of AI-generated JavaScript.
11.4 CV Studio

optionally paste job description → generate → edit → preview → export PDF or DOCX →
save to My Documents.
Templates: ATS-Friendly, Minimal Professional, Modern, Academic, Executive, each with a
distinct layout.

11.5 Cover Letter Studio
Inputs: profile, company name, job title, job description, tone (for example formal, warm,
confident, concise).
Output: a full letter in a clean document editor with preview, export and saved versions.
Guardrails: uses only verified profile data; does not invent company facts or
achievements. Where company information is missing, the letter stays general or asks the
user.
11.6 My Documents
Library of CVs, cover letters, portfolios, certificates, imported documents and generated
assets.
Search, filter by type, sort by date.
Card or list view with preview.
Actions: preview, download, rename, version history, delete (with confirmation).
Meaningful empty states that point to the relevant Studio.
11.7 Settings
Account, Profile Preferences, Connected Accounts (disconnect and delete imported
data), Privacy, Data Export, Account Deletion, Theme, Language, Notifications.
Destructive actions sit in a clearly separated danger zone with explicit confirmation.

13. AI Interaction Design
Generation buttons call the real backend; no hardcoded outputs.
A visible "Generating…" state with the option to cancel.
Generated content is marked as a draft until the user edits or accepts it.
Where information is missing, the interface asks a specific question ("What was your
end date at this role?") instead of guessing.
Every generated asset is saved and versioned, with restore.
AI suggestions for summaries are shown as proposals the user can accept, edit or
reject.

15. Accessibility
WCAG 2.2 AA contrast for all text and controls.
Full keyboard navigation with visible focus rings in the accent blue.
Semantic landmarks, labelled form fields, and error messages tied to inputs.
Reduced-motion support; no information conveyed by colour alone.
Touch targets at least 44 × 44 px.
Exported PDFs from the ATS template must have selectable text and a logical reading
order.
